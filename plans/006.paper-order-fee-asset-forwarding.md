# 006 — forward paper's third-asset fee reporting

Plan for [`specs/006.paper-order-fee-asset-forwarding.md`](../specs/006.paper-order-fee-asset-forwarding.md).

## Solution

- `PaperOrderMessage` (`src/userStream.ts`) gains `feeAsset?: string`,
  next to the `feePaid`/`feeSide` spec 005 added.
- `preparePaperOrderMsg` gains one more present-if-present spread,
  identical in shape to the two spec 005 already added:

  ```ts
  ...(msg.feeAsset !== undefined ? { feeAsset: msg.feeAsset } : {}),
  ```

Root cause spec 006 names: the field simply wasn't declared or copied
yet, because paper never sent it until now.

## Why no extraction

JIT tier **0**. One field, one line, following an established pattern
in the same function twice already.

## Blast radius

1. **Other call sites.** Same as spec 005 — `preparePaperOrderMsg` has
   one call site (`:3612`), `PaperOrderMessage` is used only by the
   paper `cbOrder` callback and `paperTradingWS.ts`'s type import
   (structural pass-through, no change needed there).
2. **`core/` submodule.** `websocket-connector-sh` — parent pointer
   bump at ship time, alongside `paper-trading-sh` spec 004's pointer
   bump. Either can ship first; the bug (missing `feeAsset` on the
   paper live-stream path) isn't closed until both are live.
3. **Contracts this repo owns.** `ExecutionReport` gains no new field
   (it already had `feeAsset` from spec 003) — this is strictly
   narrower than spec 005's change, which did add a field
   (`feeSide`). Non-breaking for every existing consumer.
4. **Other tests.** `venueFeeForwarding.test.ts` (spec 003) and
   `paperOrderFeeForwarding.test.ts` (spec 005) both exercise adjacent
   code in the same file — untouched, must stay green.
