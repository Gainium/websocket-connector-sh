# Plan 011 — binanceUS candle URL 404 (revision 2: URL only)

Implements spec `011.binanceus-candle-url-404-restart-storm.md` **revision 2**.
One file: `src/price/binance.ts`.

> Revision 1 of this plan had a Step 2 that scoped `binanceErrorCb`'s recovery
> to the faulting client. Its justifying claim was refuted in production (spec
> §4) and the deploy was rolled back, so Step 2 is **withdrawn**: this plan is
> Step 1 only, and `binanceErrorCb` returns to the family-wide
> `stopBinance()` + `init()` it has always had.

## Build order

### Step 1 — §2.1, the URL

In `connectBinanceCandleStreams`, replace the `us` branch's
`getWsUrl(WS_KEY_MAP.main)` interpolation with the hardcoded combined-stream
endpoint, matching the three sibling branches in the same `for` loop:

```ts
`wss://stream.binance.us:9443/stream?streams=${wsKey}`
```

`getWsUrl()` cannot be reused here: it is the SDK's *client-wide* URL builder
and appends a connection-type suffix to the `settings.wsUrl` override, which
is set to the raw `/ws` path for the ticker client. There is no SDK helper for
"combined stream endpoint for this client", which is why all three siblings
already hardcode. The `//@ts-ignore` becomes `//@ts-expect-error` to match them
(`connectToWsUrl` is private).

**Not** touching `settings.wsUrl` (:194-199) — the ticker client needs `/ws`
(spec §3). **Not** touching `binanceErrorCb`, `restartBinanceClient` (removed)
or `stopBinance` — spec §4.

## Contract decisions the spec left open

- **Hardcode vs. derive the US host.** Hardcode. The host already appears at
  :195; a shared constant would mean editing the ticker path, which spec §3
  puts out of scope, for no behavioural gain. Consistency with the three
  siblings is the lower-risk choice — and the divergence from them is the
  defect (spec §2 origin), so converging on their shape *is* the fix.
- **Reuse before writing.** There is no existing URL-building helper to apply:
  `getWsUrl` is the SDK's and is the wrong one (spec §1.2a); the repo has no
  local combined-stream builder — the three siblings are string literals. Adding
  one would be a four-call-site refactor spanning the ticker path that spec §3
  excludes. No new helper is introduced.

## Blast Radius

1. **Other call sites.** `connectBinanceCandleStreams` — `subscribeCandleCb`,
   `reconnectBinanceCandleStream` and its own debounce timer. All private to
   `BinanceConnector`; its only export is the class, so no external importer
   reaches them. The changed expression is inside one `if (us)` branch: nothing
   outside the binanceUS candle path can observe it.
2. **`core/` submodule — yes.** This is `websocket-connector-sh`, consumed by
   the prod `binance-websocket` and `websocket-connector` checkouts and by
   self-hosted deployments (root CLAUDE.md Danger List #11). The parent pointer
   needs bumping. Mitigation: the change is one URL string on one venue's
   candle path.
3. **Owned/emitted contracts — none touched.** The Redis channels
   `trade@{symbol}@{exchange}` and `{symbol}@{exchange}@{interval}Candle`, their
   payloads, the `archiveCandleWrite` RabbitMQ shape and the paper-trading
   socket.io bridge are all downstream of `cbWs`/`cbWsTrade`, untouched here.
   No exported type, signature or enum changes.
4. **Other tests on this path.** `test/binanceUsPriceGate.test.ts` drives the
   real `initBinanceWS` against fake clients and asserts which sockets each gate
   value produces — it must stay green. Full `npm test` must stay green (84
   tests), and `tsc --noEmit` must pass in **both** `core/` and the parent.
