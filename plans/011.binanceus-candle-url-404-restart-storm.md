# Plan 011 — binanceUS candle URL 404 + family-wide restart storm

Implements spec `011.binanceus-candle-url-404-restart-storm.md`.
One file: `src/price/binance.ts`.

## Build order

### Step 1 — §2.1, the URL (independently shippable, stops the live storm)

In `connectBinanceCandleStreams`, replace the `us` branch's
`getWsUrl(WS_KEY_MAP.main)` interpolation with the hardcoded combined-stream
endpoint, matching the three sibling branches in the same `for` loop:

```ts
`wss://stream.binance.us:9443/stream?streams=${wsKey}`
```

`getWsUrl()` cannot be reused here: it is the SDK's *client-wide* URL builder
and appends a connection-type suffix to the `settings.wsUrl` override, which
is set to the raw `/ws` path for the ticker client. There is no SDK helper for
"combined stream endpoint for this client", which is why all three siblings
already hardcode. The `//@ts-ignore` becomes `//@ts-expect-error` to match them
(`connectToWsUrl` is private).

**Not** touching `settings.wsUrl` (:194-199) — the ticker client needs `/ws`
(spec §3).

### Step 2 — §2.2/§1.1c, the recovery radius

`binanceErrorCb(e)` → `binanceErrorCb(e, type)`; the one call site
(`getBinanceClient`) already has `type` in scope. Replace `stopBinance()` +
`init()` with `restartBinanceClient(e, type)`, guarded by a
`binanceRestarting: Set<string>` keyed `${e}:${type}` that **drops** (not
queues) concurrent restarts — `bybit.ts`' Bug #121 note explains why the
`IdMutex` used elsewhere in this file is wrong for this: it serialises, so N
exceptions still run N cycles.

`restartBinanceClient` rebuilds exactly one client via the existing
`getBinanceClient(e, type, current)` — which already retires the outgoing
client (`removeAllListeners` + `closeAll` + a no-op `exception` handler, so a
dying socket cannot re-enter) — then re-subscribes only that client:

| client | recovery |
|---|---|
| ticker + `binance` / `binanceUS` | `subscribeSpotAllMini24hrTickers()` |
| ticker + `binanceCoinm` / `binanceUsdm` | `subscribeAll24hrTickers('coinm' \| 'usdm')` |
| candle + any | `connectBinanceCandleStreams(us, futures)` |

It re-checks the same gates `init()` applies, so a venue this worker does not
serve is never revived: `isUs`/`isIntl` per venue, `!isCandle || isAll` for
tickers, `isCandle || isAll` for candles.

`stopBinance()` stays — `stop()` is still its caller, and that one *should* be
family-wide.

## Contract decisions the spec left open

- **Hardcode vs. derive the US host.** Hardcode. The host already appears at
  :195; a shared constant would mean editing the ticker path, which spec §3
  puts out of scope, for no behavioural gain. Consistency with the three
  siblings is the lower-risk choice.
- **Coalesce per client, not globally.** Key is `${exchange}:${type}`. A global
  flag would let a flapping US client suppress a genuine intl recovery — the
  same coupling this spec exists to remove.
- **Errors still log at `error` level.** `bybit.ts` demotes known-benign
  replies to `info`; binance has no equivalent benign-message set, and
  inventing one is not evidence-backed. Volume drops because the storm stops,
  not because lines are hidden.

## Blast Radius

1. **Other call sites.** `binanceErrorCb` — one, `getBinanceClient` (:203).
   `stopBinance` — after this change one, `stop()` (:441); the `binanceErrorCb`
   caller is removed. `connectBinanceCandleStreams` — `subscribeCandleCb`,
   `reconnectBinanceCandleStream`, its own debounce timer, and now
   `restartBinanceClient`. All private to this class; grepped, no external
   importer reaches them (`BinanceConnector`'s only export is the class).
2. **`core/` submodule — yes.** This is `websocket-connector-sh`, consumed by
   the prod `binance-websocket` and `websocket-connector` checkouts and by
   self-hosted deployments (root CLAUDE.md Danger List #11). The parent pointer
   needs bumping. Mitigation: the change is confined to one class's private
   reconnect internals.
3. **Owned/emitted contracts — none touched.** The Redis channels
   `trade@{symbol}@{exchange}` and `{symbol}@{exchange}@{interval}Candle`, their
   payloads, the `archiveCandleWrite` RabbitMQ shape and the paper-trading
   socket.io bridge are all downstream of `cbWs`/`cbWsTrade`, which this change
   does not touch. No exported type, signature or enum changes —
   `binanceErrorCb` and `restartBinanceClient` are `private`.
4. **Other tests on this path.** `test/binanceUsPriceGate.test.ts` drives the
   real `initBinanceWS` against fake clients and asserts which sockets each
   gate value produces — it must stay green, and it is the guard that step 2
   did not change what `init()` subscribes. Full `npm test` must stay green.

## JIT legacy tier

**Tier 1.** `restartBinanceClient` is extracted as its own named, tested unit,
but stays infra-coupled (it holds the SDK client fields). Tier 2 would mean a
pure "which client + which subscription" decision function; the switch is a
field-assignment table over eight instance fields, so purity would buy an
indirection and no extra testability — the recording-fake harness already
exercises it end to end. Tier 3 is out of the question for a live-incident fix
in a shared `core/`.
