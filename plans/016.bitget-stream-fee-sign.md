# 016 — Bitget stream fees reach the platform as a cost — plan

Spec: `specs/016.bitget-stream-fee-sign.md`.

## Solution

One pure function, `bitgetFeeCost(fee)` in `src/utils/bitgetFee.ts`: a
negative number loses its leading `-`; anything else (positive, zero,
unparseable, absent) is returned untouched. Both Bitget order mappers in
`src/userStream.ts` — `prepareBitgetOrderMsg` (classic) and
`prepareBitgetUtaOrderMsg` (unified account) — pass every `feeDetail[].fee`
through it for `feeBreakdown[].amount` and for `feePaid`.

Contract decisions the spec left open:

- **Strip the sign on the string, not `Math.abs` on a number.** The venue's
  own digits survive exactly (no float re-rendering of tiny fees).
- **Positive values are left as they are**, not re-interpreted. REST
  (`normalizeOrderFees`) takes the magnitude of both signs, so for a
  negative charge both paths now agree; for a positive value this diff
  changes nothing (§1.3), so it cannot turn anything new into a cost.
- **Both Bitget stream mappers**, not only the classic one: the unified
  mapper forwards the same `feeDetail` the same way, and REST's
  `convertUtaOrder` already normalizes it through `normalizeOrderFees`.
- **Zero stays as forwarded** (`'0'`): main-app already treats a
  non-positive value as "not observed".

JIT tier: Tier 2 — the rule is a pure function with its own test; the
mappers stay as they are otherwise. No wider extraction.

## Blast Radius

1. Call sites: `bitgetFeeCost` is new; only the two Bitget mappers call it.
   No other venue's mapper is touched — OKX/Hyperliquid/Bybit/Coinbase/
   Kraken output is unchanged.
2. Under `core/` (websocket-connector-sh): public, consumed by both prod
   checkouts. The parent pointer bump happens at ship.
3. Contract: the `ExecutionReport` published to Redis for main-app. The
   shape is unchanged; only the sign of Bitget fee amounts. main-app's
   consumer already defines these fields as costs (`orderFee.ts`), so this
   moves the producer onto the consumer's documented convention.
4. Other tests on this path: `test/venueFeeForwarding.test.ts` (Bitget
   cases asserted the old signed value — updated to the cost) and
   `test/bitgetUtaStream.test.ts` (positive fee, must stay green).
