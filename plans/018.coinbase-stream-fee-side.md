# 018 — Coinbase stream fee side: plan

## Solution

`prepareCoinbaseOrderMsg` adds `feeSide: 'quote'` beside `feePaid:
order.total_fees`. This resolves 003 §4's open question the way the
exchange-connector REST mapper already did, so a Coinbase order states the
same fee shape whichever path delivered its fill.

JIT tier: 1. One field on an existing object literal; no extraction.

## Blast Radius

1. Call sites: `prepareCoinbaseOrderMsg` has one caller (the Coinbase
   user-channel handler).
2. Under `core/` (websocket-connector-sh), which is public and deployed via
   the parent `websocket-connector`; the parent pointer needs a bump.
3. Contract: `feeSide` is already an optional field of the published
   `ExecutionReport` (paper sets it, spec 005) and main-app already copies
   it (`streamFeeFields`) and persists it (`orders.feeSide`). No new field.
4. main-app effect: Coinbase orders filled over the stream now book their
   observed fee in deal profit, `commission`, `feePaid`, the fee ledger and
   combo/grid transactions, as MARKET orders already do. Close quantity is
   not changed: the only sizing reader of an observed split
   (`comboEntryBaseFee`) uses its `base` leg, which stays 0, and
   `ordersFeeIsThirdAssetOnly` treats the order as on-pair (it was neither
   on-pair nor third-asset before, which also returned false). Combo TP
   price targets include `fullFee`, which now carries the observed fee for
   these orders, the same as for MARKET orders.
5. Tests that must stay green: `test/venueFeeForwarding.test.ts`,
   `test/coinbasePartialFill.test.ts`, and the rest of `npm test`.
