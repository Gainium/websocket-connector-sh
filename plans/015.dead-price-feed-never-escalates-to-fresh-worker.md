# Plan 015 — escalate a dead feed to a fresh worker

## Build order

1. `src/price/stallEscalation.ts` — pure: `stallOf(message)` parses the three
   watchdog stall messages into `{exchange, kind}`. `StallCounter` keeps
   per-feed consecutive counts (`noteStall` returns true at the threshold,
   `noteData` resets), plus one module-level `stallCounter` per thread. It
   lives in its own module because it has to outlive the connectors
   `service.ts` rebuilds.
2. `src/price/common.ts` — `cbWs` → `noteData(exchange,'price')`,
   `noteCandleActivity` → `noteData(exchange,'candle')`. These are the same two
   liveness points that already reset `targetedRestartCount`.
3. `src/price/service.ts` — `uncaughtException` only (the watchdog throws
   synchronously from a timer, so a stall never arrives as a rejection): after
   the skip/lock checks and the log, `stallOf` → `noteStall` → `process.exit(1)`
   at the threshold. In a worker thread, `process.exit` ends only that thread.

## Contract decisions

- Threshold 3: about 2.5–3 minutes at the 50s watchdog, as the brief asked.
- The count is keyed by kind as well as exchange, so in the `all` role flowing
  candles cannot mask a dead ticker feed.
- The existing `retry` bookkeeping is left as is. Fixing its comparison would
  change the reaction to any two errors within 60s, including non-stall ones,
  and that falls under §4.

## Blast Radius

- Only the price/candle worker threads. No Redis channel, payload, RabbitMQ or
  socket contract changes.
- One exiting worker restarts its whole family (e.g. the Bitget worker covers
  spot, USDM and COIN-M), so healthy siblings see a sub-minute reconnect. That
  is the same thing the in-thread rebuild already does to them on every stall.
- If a venue stays down for hours, the worker is replaced about every 3 minutes
  instead of being rebuilt about every minute in-thread, so the restart rate is
  lower. Each fresh worker re-fetches exchange info once.
- The market-archive preload (parent `src/archive/preload.ts`) wraps
  `cbWsTrade`, which still calls `noteCandleActivity`, so nothing changes there.
