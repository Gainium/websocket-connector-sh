# 021 — plan

## Build order

1. `clearStaleKrakenAuth(store, wsKey)` — exported, takes only the two WsStore
   methods it uses (Tier 1 extraction: a named, tested unit on the touched path).
2. Kraken `reconnected` handler calls it, logs when it dropped something.
3. Futures-only auth watchdog armed on `open` and `reconnected`, cleared on
   `authenticated` and in `close()`. On expiry: `close()`, drop the room from
   `users`/`subscribersMap`, `scheduleAuthSelfHeal(…, 1000)`.

## Blast radius

- Call sites: only the Kraken branch of `openStreamCallback`; Binance, Bybit,
  Bitget, OKX, KuCoin, Coinbase, HL untouched.
- `core/` is this repo (public, shared): consumers must bump their pointer.
- Emitted contracts unchanged — same Redis channels and payloads; only new log
  lines and an extra rebuild in a failure mode that previously stayed deaf.
- Existing Kraken tests (`krakenFillCumulative`, `krakenSpot*`) must stay green.
- SDK upgrade: test §4.1/1 asserts the SDK bug itself, so an upgrade that fixes
  it fails that test loudly and the workaround can be retired.
