# Plan 012 — Binance `exception` payload is empty

Implements spec `012.binance-ws-exception-payload-is-empty.md`.
One source file: `src/price/binance.ts`.

## Build order

### Step 1 — §4.1/§4.2, read both shapes

Add a module-level `describeWsException(data)` to `src/price/binance.ts` that
builds one flat record from:

1. the payload's own enumerable properties, minus `wsKey` (already in the
   prefix) — this covers the SDK's non-transport `exception` sites;
2. the orphaned `ws` event slots, mapped by symbol description:
   `kMessage → message`, `kError → error`, `kType → type`, `kCode → code`,
   `kReason → reason`, `kTarget → url` (taking only `target.url`, never the
   socket object).

Own properties win over symbol slots on a name collision, since a property the
SDK set deliberately is better evidence than a slot the spread left behind. An
`Error` value is reduced to `` `${name}: ${message}` ``, which is what
`JSON.stringify` drops.

### Step 2 — §4.3/§4.4/§4.5, serialize

Serialize the record with the repo's existing `safeStringify`
(`src/utils/redact.ts`), not `JSON.stringify`. Cap the payload so one line stays
one readable line. If nothing at all was extracted, fall back to
`safeStringify(data)` for an object and `String(data)` for a primitive — the
first is today's output, so an un-improvable shape does not regress.

### Step 3 — the call site

`binanceErrorCb` swaps `JSON.stringify(data.error ?? data ?? '')` for
`describeWsException(data)`. The prefix expression, the `slice(0, 100)` on
`wsKey`, and `this.stopBinance(); this.init()` are byte-identical to before.

## Contract decisions the spec left open

- **Reuse vs. write a serialiser.** `safeStringify` already exists, already
  un-hides `Error.name`/`Error.message`, and already redacts credentials — it is
  reused rather than reimplemented, and it is the only part of this that needed
  writing from scratch had it not existed. What it cannot do is reach the `ws`
  symbol slots, and it must not learn to: `redact.ts` is declared "kept
  byte-identical in exchange-connector core and websocket-connector core", so
  editing it means porting to a second repo for a `ws`-specific quirk that
  belongs at the exception boundary. `describeWsException` therefore *normalises*
  and `safeStringify` *serialises*.

  The triage brief named `bybit.ts:265` as the formatter to reuse. It is not a
  helper — it is an inline `data.error ?? data.ret_msg` in `bybitRestartCb`, and
  applied here it yields `undefined` for every real event (spec §2.1). Not
  reusable; `safeStringify` is the real existing helper and is used instead.

- **Where it lives.** Module-local in `binance.ts`. `bybit`/`okx`/`kucoin` are
  likely to have the same shape but that is unmeasured (spec §5); lifting the
  function into `price/common.ts` on a guess would widen the change for no
  proven gain. Lifting it later is a move, not a rewrite.

- **Symbol lookup by `description`.** There is no exported handle on `ws`'s
  internal symbols, so the description string is the only key available. It is
  read defensively — an unknown description is ignored, and if `ws` ever renames
  them the fix degrades to §4.5's fallback, i.e. to today's line.

## Blast Radius

1. **Other call sites.** `describeWsException` is new and called once, from
   `binanceErrorCb`. `binanceErrorCb` is registered on all eight binance clients
   in `getBinanceClient` — that is the intended reach and the handler's
   control flow is unchanged. `safeStringify` gains one caller; it is a pure
   function and is not modified.
2. **`core/` submodule.** Yes — this is `websocket-connector-sh`, shared with
   prod `binance-websocket`. Both checkouts run this file. The parent pointer
   must be bumped at ship time.
3. **Owned/emitted contracts** (`CLAUDE.md` → *What this service OWNS / EMITS*):
   none touched. No Redis channel, no RabbitMQ payload, no socket.io event, no
   type signature. The only externally-observed shape is the **log line**, and
   its prefix `${EXCHANGE} error: ${wsKey} ` and single-line form are held
   constant by §4.3 and asserted by the test — that is what log greps and the
   `/findings` collectors match on. The payload after the prefix grows from
   `{"wsKey":"main"}` to a populated object, which is the point.
4. **Other tests on this path.** `test/binanceUsCandleUrl.test.ts` and
   `test/binanceUsPriceGate.test.ts` build the same connector and must stay
   green.
