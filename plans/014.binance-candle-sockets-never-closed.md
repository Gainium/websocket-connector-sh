# Plan 014 — Binance candle sockets are never closed

Spec: [`specs/014.binance-candle-sockets-never-closed.md`](../specs/014.binance-candle-sockets-never-closed.md).

## Solution

Keep the connector's own handle on every candle socket it dials, and close
those handles. The dial path is untouched.

All of it is in `src/price/binance.ts`.

1. **`dialledCandleSockets`** — a module-level `WeakMap<object, DialledSocket[]>`,
   keyed by SDK client. Module-level rather than a class field so it survives
   the `Object.create(prototype)` construction the test suite uses; weakly keyed
   so a client replaced by `getBinanceClient()` takes its entry with it.
   `DialledSocket` is a structural type over the four handler slots, `close()`
   and `on()` — the only members we touch on the raw `ws` object.
2. **`dialCandleSocket(client, exchange, url, wsKey)`** — the single place that
   calls the SDK-private `connectToWsUrl`, replacing the four duplicated
   `//@ts-expect-error` sites. Records the returned socket, and registers an
   `open` listener on it that reports through the existing `binanceOpenCb`
   (spec §3.3g — the client-level `open` event never fires for these sockets).
3. **`closeDialledCandleSockets(client)`** — detaches `onopen`/`onmessage`/
   `onerror`/`onclose` (spec §3.3d), calls `close()`, and forgets the list.
   Each socket is closed inside its own `try`, so one bad handle cannot stop
   the rest.
4. **`closeBinanceCandleStream`** — resolves the branch's client once, then
   `client.closeAll(false)` (kept, spec §3.3e) **and**
   `closeDialledCandleSockets(client)`.
5. **`getBinanceClient`** — the `if (current)` teardown gains
   `closeDialledCandleSockets(current)`, which is what makes `stopBinance()`
   (spec §1.1d) real.

Not doing `client.connect(wsKey, customUrl)`: rejected on the evidence in spec
§3.2 — it drops every chunk past the first on a shared key, and a per-chunk
synthetic key turns any reconnect into a `throw`-and-`exception` loop feeding
`binanceErrorCb`.

## JIT legacy tier

**Tier 1** for the dial: `connectBinanceCandleStreams`'s four inline private
calls become one named `dialCandleSocket`, which is where the tracking has to
live. It stays infra-coupled (it holds an SDK client), so it is not Tier 2.
Nothing higher: the surrounding `connectBinanceCandleStreams` debounce/chunk
logic is not on this bug's causal path (Tier 0) and a ports-and-adapters
extraction of the Binance price connector is not something to spring on a leak
fix.

## Blast radius

1. **Other call sites.** `connectToWsUrl` appears only in these four places in
   this repo (`grep -rn connectToWsUrl src/` ⇒ `src/price/binance.ts` only).
   `closeBinanceCandleStream` is called only from `connectBinanceCandleStreams`;
   `getBinanceClient` only from the field initialisers and `stopBinance()`.
   No other venue file is touched — bybit/okx/kucoin/bitget/kraken/hyperliquid
   dial through their own SDKs.
2. **`core/` submodule.** Yes — this is `websocket-connector-sh`, shared with
   the self-hosted platform and with the second prod checkout
   (`binance-websocket`). The parent's submodule pointer moves with it.
3. **Owned contracts** (`websocket-connector/CLAUDE.md`). The Redis
   `{symbol}@{exchange}@{interval}Candle` channel and the
   `archiveCandleWrite` RabbitMQ payload are **unchanged in name and shape**.
   What changes is that a superseded socket stops emitting into them — i.e.
   fewer *duplicate* closed candles, never fewer distinct ones. The live dial
   (URLs, wsKeys, chunk size, 1s spacing) is byte-identical, guarded by
   §3.3f's test and by the existing `test/binanceUsCandleUrl.test.ts`.
4. **Other tests on this path.** `test/binanceUsCandleUrl.test.ts` (spec 011,
   the four dial URLs) and `test/binanceRestartStorm.test.ts` (spec 013, the
   restart guard, which drives `stopBinance()`). Both must stay green — 011's
   fakes return `undefined` from `connectToWsUrl`, which the new code must
   tolerate.
