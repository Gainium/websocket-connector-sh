# Plan 013 — coalesce the Binance WS exception restart

Implements `specs/013.binance-ws-exception-restart-storm.md`.

## Solution

Two changes, both inside `src/price/binance.ts`, both confined to the exception
handler. The recovery's **radius** is untouched (spec §3): a fatal exception
still recreates all eight clients.

1. **`binanceRestarting` guard.** `binanceErrorCb` sets the flag and delegates to
   a new `runBinanceRestart()`; a second exception while the flag is set is
   logged at `info` and **dropped**. Not an `IdMutex` — that serialises, which
   would still run N full restarts back to back (spec §1.1a).

2. **`binanceRestartSettle = 15000`**, held after `init()` resolves.
   Spec §1.2b: `init()` only *arms* the re-dial (`connectBinanceCandleStreams`
   returns after setting a 5s debounce timer, then dials one chunk per second),
   so releasing on its promise leaves the 1s-spaced exceptions of spec §1.3 free
   to tear down the sockets the cycle just created. 15s covers the 5s debounce
   plus a typical multi-chunk dial, and is the same effective window bybit gets
   for free from the three `await sleep(5000)` inside `initBybitWS()`. It is a
   class field, matching `wsReconnect = 3500` in `price/common.ts`, so the test
   can shorten it.

3. **`isBenignWsException()`**, a module-local predicate over the string
   `describeWsException()` already produces — `handler not found`, `format
   error`, `already subscribed` logged at `info` with no restart (spec §1.1c).

### Reuse check (SKILL.md "reuse before you write")

- `sleep` — `src/utils/sleep.ts`, already imported by this file. No new timer
  helper.
- `describeWsException` — already in this file (spec 012). The benign predicate
  reads *its* output rather than re-walking the payload's symbol slots, so there
  is one serializer, not two.
- `IdMutex`/`IdMute` — already imported, deliberately **not** used: it queues.
- No new utility module; the predicate is four lines next to its only caller,
  mirroring how `bybit.ts` and `okx.ts` inline theirs.

### Honest note on the benign predicate

Probing the vendored `binance` SDK (spec §1.3) found no path that emits those
three strings today: the only `exception` payloads these price/candle clients
can raise come from `parseWsError`, whose message is a `ws` transport string.
The three markers are the vocabulary the sibling connectors classify as benign
and the predicate reads whatever `describeWsException` surfaces from *any*
`exception` site, including the SDK's generic `success === false` reply branch
whose text we do not control. It is defence that can only ever *reduce*
teardowns; it is not the load-bearing part of this fix — the guard is.

## Blast Radius

1. **Other call sites.** `binanceErrorCb` is called only from
   `getBinanceClient` (:273). `stopBinance()` has two callers: the handler and
   `stop()` — `stop()` calls it directly and is deliberately left unguarded, so
   shutdown still tears everything down immediately. `init()` is called by the
   handler and by `priceConnector`'s boot; the guard wraps only the handler's
   call. Verified by grep; nothing else in the repo references either.
2. **`core/` submodule.** Yes — this file is shared/public and deployed
   platform-wide (cloud + self-hosted). The parent pointer must be bumped
   deliberately. No exported symbol changes: everything added is `private` or
   module-local, so no consumer of `core/` sees a new or altered shape.
3. **Cross-service contracts (root CLAUDE.md Danger List).** None touched. Redis
   market-data channel names (`trade@…`, `…Candle`), the `archiveCandleWrite`
   payload and the paper-trading socket.io contract are all downstream of
   `cbWs`/`cbWsTrade`, which this change does not reach. The only observable
   difference is *fewer* teardowns, i.e. strictly more continuous publication on
   those same channels.
4. **Other tests on this path.** `binanceUsCandleUrl.test.ts` (the dial URL),
   `binanceWsExceptionPayload.test.ts` (`describeWsException`),
   `binanceUsPriceGate.test.ts`, `bybitRestartStorm.test.ts`. All must stay
   green; `binanceWsExceptionPayload` is the closest neighbour since the benign
   predicate consumes its output.

### Risk the reviewer should weigh

Holding the guard 15s means a genuinely fatal exception arriving inside the
window is dropped and our family-wide restart is deferred by up to 15s. That is
acceptable because the SDK reconnects the faulting socket on its own
(`executeReconnectableClose`, `reconnectTimeout` 3500ms — observed in the spec
§1.3 probe) and the candle debounce re-arms regardless. Today's alternative is
~1.3 teardowns/s, under which nothing connects at all.

## JIT legacy tier

**Tier 0/1.** The causal path is one 12-line handler. The restart body is lifted
into its own named `runBinanceRestart()` (Tier 1 — named, tested, still
infra-coupled) because the guard needs a `finally`. No port/adapter extraction:
`stopBinance`/`init` are this class's own methods and a Tier 3 rewrite of the
connector is exactly the scope creep the runbook warns against on a bug touch.
