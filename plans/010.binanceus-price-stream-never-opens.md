# Plan 010 — binanceUS price/candle streams never open, and the boot line hides it

Spec: [`../specs/010.binanceus-price-stream-never-opens.md`](../specs/010.binanceus-price-stream-never-opens.md)

## Solution

Two edits in `src/priceConnector.ts`. Nothing else in the repo changes — the
binanceUS client code in `src/price/binance.ts` is correct and untouched, and
spec §2 says the gate is the whole cause.

### 1. `isBinanceUS` answers from the same rules as every other gate (§1.1a, §1.1b)

```ts
get isBinanceUS() {
  return (
    this.isFamilyNeeded('binance') && isExchangeEnabled(ExchangeEnum.binanceUS)
  )
}
```

Reuse, not new logic — both halves already exist and are already the repo's
answer to this question:

- `isFamilyNeeded('binance')` is the **family** gate every other venue uses.
  It already carries the `binance`/`binanceus` env alias (:173-177) and the
  "admin-config is the sole source of truth when present" rule (:165-169). It
  has to be the family gate, because binanceUS has no worker of its own —
  `FAMILY_VARIANTS.binance` lists it and `VARIANT_TO_WORKER_KEY` routes it to
  the `binance` worker.
- `isExchangeEnabled(ExchangeEnum.binanceUS)` is the **variant** gate, imported
  in this file already and applied at `subscribeCandleCb` (:367) for exactly
  this purpose ("Variant-level admin-config gate"). It returns `true` in cloud
  builds and before the first admin-config refresh, so it is inert on prod and
  cannot introduce a boot race — and `index.price.ts:32-35` awaits
  `startAdminConfigSync()` before `new Connector()` anyway.

Rejected alternative: `isBinanceUS = this.isFamilyNeeded('binance')` alone (the
literal reading of the triage brief). It fixes prod identically, but on a
self-hosted deployment it would open a binance.us socket for an operator who
enabled only Binance intl — silently overriding an Admin → Exchanges choice in
the other direction. Adding the variant gate the class already owns costs one
`&&` and satisfies §1.1b in both directions.

Rejected alternative: a new `isVariantNeeded()` helper. It would duplicate
`isExchangeEnabled`, which the REUSE rule forbids.

### 2. `logFamilySelection` reports binanceUS as its own unit (§1.1c)

Build the on/off lists from the family keys **plus** an explicit `binanceUS`
entry driven by `this.isBinanceUS`, instead of from `Object.keys(FAMILY_VARIANTS)`
alone. Same line format, same `source` prefix, same unknown-token warning — a
venue can now only be in `streaming:` or in `NOT streaming:`, never in neither.

This is the half that matters for the next occurrence: the gate bug was
survivable for months only because the process's own boot line said
`NOT streaming: (none)` while a venue was dark.

## JIT legacy tier

**Tier 0.** The causal path is two small, already-named methods on the class
that owns the decision; the gates are already pure (no I/O — module-level env
plus an injected-by-import config snapshot). There is no I/O-mixed-with-logic
smell to cut out, so no extraction is warranted. Anything more would be a
drive-by rewrite of a file on the platform's highest-blast-radius path.

## Blast Radius

1. **Other call sites.** `isBinanceUS` is read in exactly two places, both in
   this file: `initWorker` (:420, the worker payload `binance.isUs`) and
   `init` (:508, `if (this.isBinance || this.isBinanceUS)` — already true
   whenever `isBinance` is, so the worker-spawn decision is unchanged).
   `logFamilySelection` is called once, from `init()`. Verified by grep across
   `src/` and the parent `src/`.
2. **`core/` submodule.** Yes — this is `websocket-connector-sh`, shared with
   prod `binance-websocket` and every self-hosted deployment. The parent
   pointer must be bumped at ship time. No exported type, signature or
   constant changes; the diff is two method bodies plus a log-line
   composition, so consumers cannot break at the type level.
3. **Owned contracts (`../CLAUDE.md`).** None changed. Redis channel names
   (`trade@{symbol}@{exchange}`, `{symbol}@{exchange}@{interval}Candle`),
   the RabbitMQ `archiveCandleWrite` payload and the paper-trading socket.io
   bridge are all untouched. The *effect* is that
   `trade@<sym>@binanceUS` and `<sym>@binanceUS@<interval>Candle` start being
   published — that is the fix, and consumers (main-app workers,
   paper-trading) already subscribe to them and currently receive nothing.
   Behaviour change for self-hosted operators: an admin-config set that omits
   `binanceUS` now correctly suppresses it; one that includes it now correctly
   enables it regardless of the legacy env line.
4. **Other tests on this path.** The rest of `core/test/*` covers `userStream`
   and the other price connectors; none touches `priceConnector`'s gates.
   Whole suite must stay green.
