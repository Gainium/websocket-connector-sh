# 017 — OKX stream fees: plan

## Solution

Generalise 016's `bitgetFeeCost` (`src/utils/bitgetFee.ts`) into the
venue-neutral `chargeCost` (`src/utils/feeCost.ts`): a negative fee loses
its sign, keeping the venue's own digits, and anything else is returned as
is. The Bitget mappers call it unchanged in behaviour. `prepareOkxOrderMsg`
uses it on `feePaid: data.fee`.

JIT tier: 2. The helper is already a pure function; it is renamed, not
re-designed.

## Blast Radius

1. Call sites: `bitgetFeeCost` was used only by the two Bitget mappers in
   `src/userStream.ts` (4 calls); all move to `chargeCost` with identical
   behaviour. `prepareOkxOrderMsg` has one caller (the OKX `orders` channel
   handler).
2. Under `core/` (websocket-connector-sh), which is public and deployed via
   the parent `websocket-connector`; the parent pointer needs a bump.
3. Contract: the `ExecutionReport` shape on Redis is unchanged. Only the
   sign of a negative OKX `feePaid` changes, toward what main-app already
   expects.
4. Tests that must stay green: `test/venueFeeForwarding.test.ts`,
   `test/bitgetStreamFeeSign.test.ts`, and the rest of `npm test`.
