# 011 — the binanceUS candle URL 404s, and its exception restarts all eight binance clients

Bug spec (SKILL.md Part 0). Scope: `src/price/binance.ts` — the binanceUS
candle connect URL, and the `exception` handler's recovery radius. The gate
that decides *whether* binanceUS is served (`src/priceConnector.ts`,
spec 010) is correct and out of scope: it is the thing that finally ran this
code, not the thing that is broken.

## §1 Definition

### §1.1 Expected

**§1.1a — the binanceUS candle stream connects to the combined-stream
endpoint.** `connectBinanceCandleStreams` multiplexes up to 200 `@kline_`
streams into one socket via `?streams=a/b/c`. On Binance that payload is only
valid on the **`/stream`** path; **`/ws`** is the raw single-stream path and
takes the stream name in the path, not a query. Every sibling branch in the
same `for` loop already hardcodes the combined form — spot
`wss://stream.binance.com:9443/stream?streams=`, coin-m
`wss://dstream.binance.com/stream?streams=`, usd-m
`wss://fstream.binance.com/market/stream?streams=`. binanceUS must use
`wss://stream.binance.us:9443/stream?streams=` for the same reason.

**§1.1b — a venue that cannot connect degrades only itself.** The binance
family worker owns eight clients — spot, coin-m, usd-m and US, each with a
ticker and a candle client. An `exception` from one of them must recover that
client. A venue that is unreachable (geo-blocked, delisted, misconfigured, or
simply down) must not be able to interrupt the other seven, because those
seven carry the live price and candle feed for every non-US binance pair.

**§1.1c — recovery coalesces rather than compounds.** Identical reasoning to
`bybit.ts`' Bug #121 note: a burst of exceptions must drop concurrent
restarts, not queue them, or N exceptions produce N full restart cycles.

### §1.2 Actual

**§1.2a — the URL is built from `getWsUrl`, which yields `/ws/stream`.**
`src/price/binance.ts:409-412`:

```ts
this.binanceClientCandleUs.connectToWsUrl(
  `${await this.binanceClientCandleUs.getWsUrl(WS_KEY_MAP.main)}?streams=${wsKey}`,
  WS_KEY_MAP.main,
)
```

The US clients are constructed with `settings.wsUrl =
'wss://stream.binance.us:9443/ws'` (:194-199) — correct for the *ticker*
client, which uses the raw single-stream path. The SDK's `getWsUrl()` returns
that override **and then appends its own `/stream` suffix**
(`binance@3.6.3`, `websocket-client.js:271` → `getWsUrl(...) +
getWsURLSuffix(...)`), so the candle client connects to:

```
wss://stream.binance.us:9443/ws/stream?streams=btcusdt@kline_1m/...
```

`/ws/stream` is neither endpoint. Binance.US answers **HTTP 404** and the
socket never opens.

**§1.2b — the exception handler restarts everything.**
`binanceErrorCb` (:168-179) ends in `this.stopBinance()` + `this.init()`.
`stopBinance()` (:207-248) rebuilds **all eight** clients, and `init()`
re-subscribes every ticker and re-opens every candle stream. So the US candle
client's 404 tears down the healthy intl spot/coin-m/usd-m feeds; each
teardown raises fresh intl `exception`s, which re-enter `binanceErrorCb`, which
tears everything down again. The loop is self-sustaining and never converges,
because the US client can never succeed (§1.2a).

### §1.4 User-visible consequence

The binance family worker serves spot, coin-m and usd-m — the platform's
highest-volume venues — from the same process. Since 2026-09-17T19:14Z its
candle clients have been torn down and rebuilt every few seconds around the
clock, so closed-candle delivery to `{symbol}@{exchange}@{interval}Candle` is
repeatedly interrupted for every binance pair, not only US ones. Indicator and
candle-close driven checks evaluate on whatever survives the churn. The 12
binanceUS bots that spec 010 set out to rescue are still on the 2.5-minute
REST poll, because their socket 404s.

## §2 Assumption (hypothesis)

Two defects, one of which was dormant:

- **§2.1** `getWsUrl(WS_KEY_MAP.main)` is the wrong builder for a combined
  stream. Hardcoding `wss://stream.binance.us:9443/stream?streams=` — exactly
  as the three sibling branches already do — makes the socket open.
- **§2.2** `binanceErrorCb`'s `stopBinance()` + `init()` is a family-wide
  recovery for a per-client fault. Scoping it to the client that raised, with
  a per-client coalescing guard, means no venue can ever again interrupt the
  other seven. §2.1 alone stops *this* storm; §2.2 is what stops the next one,
  and is why an intl outage was ever possible from a US fault.

Both lines predate the onset by more than a year (`git blame`: :410 →
`42366161`, 2025-07-02; :176 → `38b5d4f`, 2025-06-26; :177 → `d64788da`,
2025-08-05). They were unreachable because `isUs` was always `false`. Spec
010's gate fix is what executed them for the first time.

## §3 Out of scope

- The `isBinanceUS` gate (spec 010). It is correct and stays as-is: the answer
  to "binanceUS 404s" is to fix the URL, never to re-dark the venue.
- `settings.wsUrl = 'wss://stream.binance.us:9443/ws'` (:194-199). It is right
  for the ticker client, which is the only other consumer of the US settings.
- The ticker-side `subscribeSpotAllMini24hrTickers()` path for binanceUS — it
  uses the SDK's own subscribe helper, not `connectToWsUrl`, and is unaffected.
