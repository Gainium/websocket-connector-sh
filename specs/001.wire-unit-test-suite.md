# 001 — Wire the existing `node:test` suite into CI

## §1. Behaviour today

This repo has a real test runner already: `npm test` runs
`node:test` (via `ts-node/register`, transpile-only) over `test/*.test.ts`
(§1.1). Five spec files exist under `test/`, each a characterization test
for a specific prod incident (Kraken cumulative fills, Coinbase partial
fill, Bybit restart storm, user-stream auth backoff, Hyperliquid fill
park). None of this runs anywhere except a developer's own machine —
there is no CI job that invokes `npm test`. The only workflow that exists
today is `.github/workflows/dco.yml`, which checks commit sign-off, not
code correctness (§1.2). A PR can merge with a red test suite and nobody
finds out until it breaks in prod.

## §2. Desired behaviour

Every pull request against this repo runs `npm test` in CI and the PR
check fails if any test fails (§2.1). No new test framework is being
introduced — this is wiring, not authoring (§2.2).

## §3. Open questions / assumptions

- §3.1 Node version for CI: no `.nvmrc` / `engines` field exists in this
  repo. `@nktkas/hyperliquid` declares `engines.node >= 24`, but the repo
  currently develops fine on Node 22 (an EBADENGINE *warning*, not a
  failure). Left open for the plan to decide.

## §4. Evidence — the suite is currently red

Running `npm test` on `main` today: 25 pass, 1 fail.
`test/hyperliquidFillPark.test.ts` fails at import time with
`Cannot find module '../../core/src/utils/common'` — this repo (the `-sh`
source repo) has no `core/` directory; that path only resolves from the
downstream `websocket-connector` consumer repo, which submodules this one
under `core/`. The equivalents exist locally: `ExchangeEnum` is exported
from `./src/utils/common.ts` and `CommonOrder` from `./type.ts` (both
already imported correctly, by relative path, from `src/utils/hyperliquidFillPark.ts`
itself). §2.1 ("CI fails if any test fails") cannot be satisfied while this
import is broken — the spec-file bug is in scope for this change, as a
one-line path correction, not new test authoring.
