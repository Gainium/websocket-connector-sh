# 006 — forward paper's third-asset fee reporting

Feature spec. Extends spec 005 (this repo) — `feePaid`/`feeSide` — to
also forward `feeAsset`, now that `paper-trading-sh` can report a
symbol's fee as paid in a configurable third asset instead of splitting
it onto `feeSide` (`paper-trading-sh` spec 004).

## Behaviour

`preparePaperOrderMsg` forwards `feeAsset` from `PaperOrderMessage`
onto the outgoing `ExecutionReport`, present-if-present — the same
rule spec 005 already applies to `feePaid`/`feeSide`, and the same
rule this repo's five real-venue normalizers already apply to their
own `feeAsset` (spec 003).

`PaperOrderMessage` gains `feeAsset?: string` to carry it in from the
paper bridge. `ExecutionReport` already declares `feeAsset` (spec 003,
real-venue path) — no type change needed there.

paper-trading never sets `feeAsset` and `feeSide` on the same order
(mirrors `CommonOrder.feeAsset`'s own contract: "When set, `feeSide`
is absent") — this repo does not need to enforce that; it only
forwards whichever one arrived.

## Evidence

Read directly: `PaperOrderMessage` (`src/userStream.ts:430-449`,
current state after spec 005) has `feePaid`/`feeSide` but not
`feeAsset`. `preparePaperOrderMsg` (`:4194-...`) copies the two it has;
grepped for `feeAsset` in that function body — zero matches.
`ExecutionReport`'s `feeAsset` field (`:277`, pre-existing, spec 003)
is untyped-restricted to nothing paper-specific — safe to reuse
as-is.

## Assumption

Purely additive: one field on `PaperOrderMessage`, one copy line in
`preparePaperOrderMsg`, mirroring the two that already exist for
`feePaid`/`feeSide`. Nothing else on this path changes.

## Out of scope

- `feeBreakdown`/`feePaidUsd` on the paper path — paper never sets
  these.
- app's consumption of `feeAsset` on a paper order — already handled
  unconditionally there since before this session (real-venue path);
  no app-side change needed (confirmed while investigating this
  session's earlier `feeSide` gap, spec 017 in `main-app-sh`).
