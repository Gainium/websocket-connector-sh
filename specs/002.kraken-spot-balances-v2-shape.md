# 002 — Kraken spot balance updates never reach main-app

Bug spec. Plan: `plans/002.kraken-spot-balances-v2-shape.md`.

## §1 Definition
- §1.1 Expected: every `balances` message on a Kraken spot private WebSocket
  (v2) is converted to an `outboundAccountPosition` event and published on the
  account channel, exactly like Kraken futures and every other venue, so the
  dashboard `balances` rows follow the venue within seconds.
- §1.2 Actual: no Kraken spot balance event is ever published. On 2026-09-03
  the `balances` collection showed 24 Kraken spot accounts with 0 rows updated
  in the last 30 min and 5 in 6 h (only REST refreshes), while Kraken futures
  had 6,651 rows updated in 30 min. A user saw 13.5 ETH on the dashboard with
  1.53 ETH on Kraken after a sale; a manual refresh fixed it.

## §2 Evidence
- Prod `balances` freshness per exchange (read-only aggregate, 2026-09-03 15:12Z).
- User-stream connector log: hundreds of `krakenexecutions` / `krakenopen_orders`
  / `krakenfills` events today, zero `krakenbalances`.
- `src/userStream.ts` `prepareKrakenBalanceMsg`: the three accepted shapes are
  a bare array, `{holding}` and `{flex_futures}`; the message handler passes the
  whole v2 message `{channel:'balances', type, data:[…]}`.

## §3 Assumption
The v2 message shape falls through every branch, `balances` stays empty and the
function returns undefined. `test/krakenSpotBalances.test.ts` fails on the
unpatched converter for exactly that reason.

## §4 Required behaviour
- §4.1 A spot v2 `balances` snapshot or update becomes an
  `outboundAccountPosition` with one entry per `data` item, `free` = the
  item's `balance` (the new total), asset passed through the Kraken asset map.
- §4.2 The entry carries **no `locked` field**: v2 gives no hold figure and a
  `'0'` would overstate "available". Consumers must leave `locked` untouched
  when absent (main-app core 1.57.1).
- §4.3 Futures `holding` / `flex_futures` conversion is unchanged.
- §4.4 An empty `data` array still yields undefined (nothing published).
