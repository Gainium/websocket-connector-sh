# 010 — binanceUS price/candle streams never open, and the boot line hides it

Bug spec (SKILL.md Part 0). Scope: `src/priceConnector.ts` — the family
allow-list that decides which exchange workers this process runs, and the
one-line boot summary of that decision. Everything downstream
(`src/price/binance.ts`, the bot-side price-gap tracker in `app-sh`) is
correct and out of scope.

## §1 Definition

### §1.1 Expected

**§1.1a — the two binance env tokens are aliases on every gate.**
`PRICE_CONNECTOR_EXCHANGES` is a *family*-level allow-list. `isFamilyNeeded`
already treats `binance` and `binanceus` as aliases for the one `binance`
family (the family worker serves spot, coin-m, usd-m **and** binanceUS from a
single `Worker`). Every per-venue gate fed into that worker must answer from
the same rule: listing `binance` must enable the binanceUS sockets exactly as
it enables the intl ones, because there is no separate `binanceUS` worker to
enable.

**§1.1b — admin-config governs binanceUS like every other variant.**
When the self-hosted admin-config set is present it is the sole source of
truth (`isFamilyNeeded`'s contract, and the variant-level gate
`isExchangeEnabled` already applied at `subscribeCandleCb`). A binanceUS
gate that consults only the env ignores the operator's Admin → Exchanges
choice in both directions.

**§1.1c — a venue that is not being streamed appears in `NOT streaming:`.**
`logFamilySelection` exists so that a gated-off venue is visible from this
process's own log; its own comment says so. A venue must appear in exactly one
of the two lists — never in neither.

### §1.2 Actual

`isBinanceUS` is the only gate in the class that does not route through
`isFamilyNeeded`: it reads the raw env and demands the literal `binanceus`
token (`src/priceConnector.ts:184-186`).

- With a `PRICE_CONNECTOR_EXCHANGES` that lists `binance` but not `binanceus`,
  `isBinance` is true so the binance family worker spawns — but it is
  constructed with `binance.isUs = false`. In `src/price/binance.ts` that
  means `initBinanceWS()` never calls
  `binanceClientUs.subscribeSpotAllMini24hrTickers()` (:311-313) and
  `subscribeCandleCb` never calls `connectBinanceCandleStreams(true)`
  (:274-276). **No binanceUS websocket is ever opened, for ticks or candles.**
- With admin-config present, `isBinanceUS` ignores it entirely: it answers
  from the env, which on an sh deployment is the line the operator was told
  stops being consulted.

`logFamilySelection` (:231-233) enumerates `Object.keys(FAMILY_VARIANTS)`, and
binanceUS is not a key — it is folded inside the `binance` family. So a
gated-off binanceUS is in neither `streaming:` nor `NOT streaming:`: the boot
line reads as if nothing were disabled.

### §1.3 Evidence (production, read-only)

- Boot line, `Gainium <-> Binance price stream connector`, every restart from
  2026-09-07 to 2026-09-17:
  `Price connector families [PRICE_CONNECTOR_EXCHANGES] | streaming:
  bybit,binance,okx,kucoin,bitget,hyperliquid,kraken,coinbase | NOT streaming:
  (none)` — source is the env, all eight families on, nothing reported off,
  and binanceUS is named nowhere.
- `BINANCEUS <type> opened …` (the per-client open callback,
  `src/price/binance.ts:157-165`) has **never** been logged by either the
  price or the candle connector — across all 91/90 live+archived log files the
  only matches are `BINANCEUSDM`. The binanceUS clients have never connected.
- The candle connector *accepts* the requests and then silently does nothing:
  `Received candle request SOLUSDT binanceUS 1h` / `Subscribe candle SOLUSDT
  binanceUS 1h`, 336 such lines, with no matching stream open.
- Downstream, `Gainium-Combo-bot`: `Still no live price stream for ETHUSDT on
  binanceUS after 1090m — still REST polling.` — 657 binanceUS lines, one hour
  apart, never a `Live price stream resumed`. The gap is permanent, not
  flapping.
- Prod Mongo, read-only: 12 bots are currently `open` on `binanceUS`
  (11 `dcabots` + 1 `combobots`) across 6 distinct users. Every one of them
  has been on the 2.5-minute REST price poll for the whole life of the
  allow-list.

### §1.4 User-visible consequence

Take-profit, stop-loss, trailing and DCA-level checks for every binanceUS bot
evaluate on a ~2.5-minute grid instead of per tick, permanently. A fast move
can cross a level and be served late. Nothing in the UI says so.

## §2 Assumption (hypothesis)

The sole cause is the gate, not the streaming code: `isBinanceUS` answers
`false` because prod's `PRICE_CONNECTOR_EXCHANGES` contains `binance` but not
the separate `binanceus` token, and that `false` is baked into the worker at
construction (`initWorker`, :418-421). Make `isBinanceUS` answer from the same
family rule as `isBinance` — plus the variant-level admin-config gate the rest
of the class already uses — and the existing, untouched binanceUS client code
connects.

Corollary: the reason this survived months is §1.1c — the boot line the
operator reads reports "NOT streaming: (none)" while a venue is dark.

## §3 Out of scope

- The Kraken/SN51 flapping in the original report: a thin-market false alarm
  per triage, and a different (real, intermittent) signal from this permanent
  one.
- `app-sh`'s price-gap tracker (`bot/main.ts`, `priceStreamGap.ts`) — it is
  what exposed this and is correct.
- `reconcileWorkers` rebuilding a live family worker when only a *variant*
  toggles under admin-config. Pre-existing and identical for every other
  variant (`binanceUsdm` off does not rebuild the binance worker either); the
  candle path is already variant-gated at `subscribeCandleCb`. A restart
  applies it. Not introduced or worsened here.
