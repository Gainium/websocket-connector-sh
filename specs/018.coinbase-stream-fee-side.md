# 018 — Coinbase stream fees name the side of the pair they were charged on

Bug spec (Definition / Evidence / Assumption). Resolves the Coinbase open
question left in [003 §4](003.forward-venue-fee-for-all-exchanges.md).

## §1 Definition

§1.1 **Expected.** When a Coinbase user-channel order update carries
`total_fees`, the `ExecutionReport` this repo publishes states both the
amount (`feePaid`) and that it was charged in the product's quote currency
(`feeSide: 'quote'`). main-app then books it, e.g. a `ZRX-USDC` sell with
`total_fees: '0.060721010856768'` as `{base: 0, quote: 0.060721010856768}`,
plus one `USDC` fee-ledger leg. This is the shape exchange-connector's
Coinbase REST mapper already emits for the same order
(`normalizeSidedOrderFee(order.total_fees, 'quote', 'charge-positive')`).

§1.2 **Actual.** `prepareCoinbaseOrderMsg` forwards `feePaid:
order.total_fees` with no `feeSide` and no `feeAsset`. main-app's
`streamFeeFields` assigns it onto the order, and `observedFeeSplit` cannot
match an empty asset against the pair, so it returns `null` and the order
falls back to the account-rate estimate; `observedFeeLegs` returns `[]`.
An order that filled after resting — every Coinbase LIMIT entry and TP —
gets its fee only from the stream, so its real fee is never booked. Under
"Ignore exchange fees" the estimate is 0, so the deal's profit carries no
fee at all.

§1.3 **Unchanged.** `feePaid` is still `total_fees` byte-for-byte. Status,
quantity, price and every other venue's mapper are unchanged. Nothing in
this repo sizes orders; in main-app, `observedFeeSplit` with a quote side
contributes no base, so close-quantity sizing (`comboEntryBaseFee`, TP
sizing) is not changed by this.

## §2 Evidence

§2.1 Code path: `src/userStream.ts` `prepareCoinbaseOrderMsg` →
`feePaid: order.total_fees` only. `WebsocketUserOrder` has no fee-currency
field (003 §1 table).

§2.2 main-app core `src/bot/main.ts` `Object.assign(order,
streamFeeFields(msg))` → `src/bot/orderFee.ts` `observedFeeSplit` (empty
`feeAsset`, no `feeSide` → `null`) → `src/bot/dcaHelper.ts` close ledger
falls back to `getUserFee`, which returns `{maker: 0, taker: 0}` under
`zeroFee`.

§2.3 Persisted prod state (read-only, Coinbase orders FILLED in the 3 days
to 2026-10-05): 5,033 LIMIT orders carry a positive `feePaid` with no
`feeSide`; MARKET orders — whose fill comes back in the REST placement
response — carry `feeSide: 'quote'` (55). The split by order type shows the
stream path ran and its output is what was persisted. Example: a LIMIT
`ZRX-USDC` TP sell of 786.50899 at 0.128672 stores `feePaid
'0.060721010856768'` with no side, and its closed deal stores `feePaid
{base: 0, quote: 0}`.

## §3 Assumption (hypothesis)

Coinbase Advanced Trade settles every trading fee in the product's quote
currency (its documented fee schedule; the REST mapper already relies on
it). Naming that side on the stream report makes main-app's existing fee
processing book the observed fee, with no main-app change.
