# 005 — paper order's fee never reaches the outgoing ExecutionReport

Bug spec. Companion to `paper-trading/core`'s spec 003
(`paper-trading` is the repo with the full cross-repo trace and
Evidence — this spec covers only this repo's slice).

## 1. Definition

### 1.1 Expected

`preparePaperOrderMsg` turns a paper-trading order push into the same
`ExecutionReport` shape a real venue's user stream produces. Once
paper-trading's socket.io `order` push carries `feePaid`/`feeSide`
(paper-trading spec 003, gate A), this repo's bridge must forward them
— the same way its five `prepare*OrderMsg` normalizers for real venues
already forward each venue's fee field (spec 003 in *this* repo,
`venueFeeForwarding.test.ts`).

### 1.2 Actual

Before this change, neither gap existed to fix from this repo's side
in isolation because paper-trading never sent the fields — but the
type and the normalizer were also not ready to receive them:
`PaperOrderMessage` (`src/userStream.ts:430-444`, pre-change) declared
no `feePaid`/`feeSide`, and `preparePaperOrderMsg`
(`:4194-4211`, pre-change) built its `ExecutionReport` as a fixed field
list that didn't reference either.

## 2. Evidence

Read directly: `PaperOrderMessage`'s pre-change field list (11 fields,
none fee-related) and `preparePaperOrderMsg`'s pre-change return object
(field-by-field, no fee reference) — both confirmed by inspection.
`ExecutionReport` itself (`:259-281`) already declares `feePaid`/
`feeAsset`/`feeBreakdown`/`feePaidUsd` for the real-venue path (this
repo's own spec 003) but not `feeSide` — the one field paper-trading
uses and real venues never do.

## 3. Assumption (hypothesis)

Two additive changes close this repo's half of the gap:

1. `PaperOrderMessage` and `ExecutionReport` both gain
   `feeSide?: 'base' | 'quote'` — `ExecutionReport` because it is the
   shared outgoing shape (this repo already puts `feeAsset` there for
   real venues; `feeSide` is paper's equivalent), `PaperOrderMessage`
   because that's what paper-trading now actually sends.
2. `preparePaperOrderMsg` copies `feePaid`/`feeSide` from `msg` when
   present, following the present-if-present rule the real-venue
   normalizers already use for their fee fields — absent must never
   become a claim of zero.

## 4. Out of scope

- `feeAsset`/`feeBreakdown`/`feePaidUsd` on the paper path — paper
  never sets these (paper-trading spec 003 §4).
- main-app's consumption of `feeSide` off this report — separate spec
  in `app`.
